The integration tests no longer wipe the first calendar they find on a server where they cannot create one (Posteo, GMX and other servers where `create-calendar` is unsupported or fragile, or where MKCALENDAR is refused and the caller gives no cal_id).  They use a calendar with `pythoncaldav-test` in its display name, the one at the test fixture's cal_id, or the one named under `test-calendar` in the server's features, and skip otherwise.  On such servers, set a calendar aside for the tests to run them again.
