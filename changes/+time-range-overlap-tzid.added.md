New server hints `search.time-range.event.overlap` and `search.time-range.todo.overlap`: whether a time-range search finds an event or task that overlaps the range without starting inside it, as RFC 4791 section 9.9 requires.  Robur only finds events whose DTSTART is in the range, Cyrus and GMX only tasks whose DTSTART is.  New server hint `search.time-range.event.tzid`: whether a time-range search places an event with a TZID and its VTIMEZONE at its time in UTC.  Infomaniak finds such an event only by a range that also reaches its local time read as UTC.  Xandikos 0.4.10 reads such a time as floating once its search index answers; the profile follows its master branch, which has the fix (https://github.com/jelmer/xandikos/pull/764).  By default the library widens every time-range search by a day and filters the result client-side, which hides both problems, except for events and tasks longer than about a day on the servers that only match start times.
