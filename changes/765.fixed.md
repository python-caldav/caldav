`complete(handle_rrule=True)` with the default `rrule_mode="safe"` left a completed copy of a recurring task behind when the server refused to save the task itself, e.g. with `ScheduleTagMismatchError` because another client had changed it.  Each retry added another copy.  The copy is now deleted before the error is raised, if the server allows that, except after a 5xx other than a rate limit or a transport error: the task may have been stored then, so the copy is kept.  The task is also reset in memory on any failure, so a retry on the same object completes the same occurrence instead of skipping one.
