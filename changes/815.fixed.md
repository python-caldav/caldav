Previously, a single calendar object with an invalid value, such as a malformed `DUE` date on a task, could cause `search()` to raise `ValueError` during client-side filtering. The caller would receive none of the matching results.

Now, the filter returns the affected object unchanged, logs its URL and the parsing error to help users identify the problem, and continues checking the remaining objects. Callers can look up the affected object by UID to inspect or repair it.
