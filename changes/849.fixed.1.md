An object caldav builds from keyword arguments, e.g. `add_event(dtstart=...)` or `add_todo(due=...)` with a time zone other than UTC, had a `TZID` without the `VTIMEZONE` that RFC 5545 section 3.6.5 requires.  A Home Assistant user reports such events shifted by the UTC offset in Synology Calendar.  The missing `VTIMEZONE` for a known time zone is now added, covering 1970 to 2100 with one `RDATE` per line, as vobject reads only the first value of an `RDATE` list in a `VTIMEZONE`.  It is left out where the server hint `save-load.icalendar.olson-tzid` says it is supported, or with `add_vtimezones=False`.
