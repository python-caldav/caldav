`save(no_overwrite=True)` no longer searches the calendar for the UID before the PUT wherever the server is known to refuse a duplicate UID at all - also where it does so unrecognisably (`save.no-uid-conflict` `ungraceful`, e.g. a bare 403), and on iCloud and Bedework.  On a server ignoring `If-None-Match: *` (SOGo), a GET of the URL replaces the search, where `save-load.stable-url` holds.  Where the server refuses the duplicate unrecognisably, the error raised for a UID taken under another URL is then whatever that refusal gives - still a `ConsistencyError` for a 412 to `If-None-Match: *` (its message then says the UID or the URL is taken), but a `PutError` or `AuthorizationError` for other statuses - rather than `UidConflictConsistencyError`.
