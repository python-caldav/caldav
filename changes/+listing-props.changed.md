`get_calendars()` keeps every property the calendar-list PROPFIND answered in each calendar's `props`, not just the display name.  That listing has always asked for `supported-calendar-component-set`, `getctag` and `calendar-color`, then thrown them away, so a client wanting a calendar's component set sent one more PROPFIND per calendar: 268 s against 6 s for 469 calendars on a Synology server.  `get_supported_components(use_cached=True)` answers from that set without asking the server.  A property the server answered 404 is left out, so it is still fetched when asked for.  Cached reads (`get_property(..., use_cached=True)`) of `getctag` and `calendar-color` now answer the listing-time value instead of asking.
