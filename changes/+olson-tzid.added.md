New server hint `save-load.icalendar.olson-tzid`: whether a server places an object whose TZID names a tz database zone correctly without a VTIMEZONE for it.  RFC 5545 requires the VTIMEZONE, so it defaults to `unsupported`; the profiles carry what the caldav-server-tester probe found, except Synology's, set by hand to `fragile` because its web UI shows such an event as UTC.  See https://github.com/python-caldav/caldav/issues/849.
