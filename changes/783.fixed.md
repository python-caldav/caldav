`get_object_by_uid()` and `get_event_by_uid()`, `get_todo_by_uid()`, ... failed on servers that refuse the search by UID, such as iCloud (412), and so did `save()` of a single recurrence, `save(no_overwrite=True)` and, with the `icloud` profile, `save(no_create=True)`.  Unless `search.text.uid` is configured as supported, a failing search now falls back to fetching `<uid>.ics`, and on a 412 (or if `search.text.uid` is unsupported or broken, in which case the search is skipped) further to listing all objects of the type.  On such servers, looking up a UID that is missing or not stored as `<uid>.ics` downloads all objects of the type, on every call.  Servers that always name an object `<uid>.ics` can say so with `forces_uid_ics` on `save-load.stable-url`, and then a missing UID does not cost a full download.
