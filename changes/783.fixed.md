`get_object_by_uid()` and `get_event_by_uid()`, `get_todo_by_uid()`, ... failed on servers that refuse the search by UID, such as iCloud (412), and so did `save()` of a single recurrence, `save(no_overwrite=True)` and, with the `icloud` profile, `save(no_create=True)`.  When the search fails, the object is now fetched as `<uid>.ics`, and failing that, found by listing all objects of the type.  On such servers, looking up a UID that is missing or not stored as `<uid>.ics` downloads all objects of the type, on every call.
